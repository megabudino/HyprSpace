WINDOW JITTER FIX - DEVELOPMENT NOTES
======================================

PROBLEM
-------
When a new window opens, it briefly appears at macOS's default position/size
before HyprSpace moves it to the correct tiled position, causing visible jitter.


WHAT WE TRIED
-------------

1. Hide in MacWindow.getOrRegister (FAILED)
   - Added hideInCorner() call after binding window to tree
   - Result: Still saw jitter
   - Root cause: Async gap between notification and hide call
   
   The flow was:
     refreshObs → Task { async } → getAxRect (await) → getBindingData (await) → hideInCorner
                  ↑
                  Window becomes visible during these awaits


DIAGNOSTIC FINDINGS
-------------------
Added timestamp logging to trace the flow:
- Notification arrives
- Window registration happens (with async gaps)
- hideInCorner executes

Confirmed the window is visible BEFORE hideInCorner runs due to async delays.


SOLUTION
--------
Act SYNCHRONOUSLY in the observer callback (refreshObs) BEFORE dispatching
any async work. The observer runs on a per-app thread and can make synchronous
AX API calls.

Two approaches documented in separate PRDs:
- prd-window-jitter-early-hide.md: Hide window offscreen immediately (simpler)
- prd-window-jitter-early-position.md: Set final position immediately (preserves Tahoe animation)

Recommended: Implement early-hide first, then optionally add early-position.
